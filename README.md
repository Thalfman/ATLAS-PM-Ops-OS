# ATLAS PM/Ops OS

**ATLAS** = **AI-enabled Tactical Learning, Automation, and Systems**

ATLAS PM/Ops OS is a local, Markdown-first operating system for project management, operations, project controls, and responsible AI workflow integration. It is designed to help Tom Halfman, PMP prepare for and then operate effectively in a Project Manager / Operations Specialist role in Motorola Solutions Applied Technology in Schaumburg, while staying conservative, credible, audit-friendly, and security-conscious.


## Purpose

This repository-style system exists to help Tom:

1. Prepare before onboarding using only safe, synthetic, public, generic, or fictional material.
2. Provide value during clearance-limited onboarding without needing access to restricted systems or cleared work areas.
3. Build repeatable PM/Ops workflows for project integrity, reporting quality, action tracking, schedule/accounting reconciliation, discrepancy resolution, SOPs, dashboards, lessons learned, and executive communication.
4. Develop responsible AI-enabled workflow patterns that can start in Gemini Enterprise or other approved tools and later migrate to approved enterprise systems.

AI integration is a major expected value area for the role. The system does **not** chase tools for their own sake. It uses AI to improve PM/Ops outcomes: cleaner reporting, better follow-through, stronger variance narratives, faster discrepancy triage, better knowledge capture, and more consistent operating rhythms.

## Hard safety boundary

Do **not** place the following into this local/personal system unless the employer explicitly approves the specific system and data handling path:

- Classified information
- CUI
- ITAR/export-controlled information
- Proprietary employer data
- Customer data
- Contract data
- Internal schedules
- Internal financials
- Internal technical documents
- Real program names that are not public
- Real meeting notes
- Real project accounting exports
- Real Microsoft Project files from employer systems
- Any employer data not explicitly approved for the tool being used

Pre-start work must use only synthetic data, public information, generic templates, fictional scenarios, or Tom-created examples.

## Operating posture

- Human-in-the-loop by default
- Approved-tool-first
- Gemini-first, platform-agnostic
- No shadow IT
- No autonomous decisions
- Audit-friendly outputs
- Clear separation between personal preparation artifacts and employer-deployable artifacts
- AI supports PM/Ops judgment; it does not replace it

## How to use ATLAS in each work session

1. Read `00_MASTER_CONTEXT/MASTER_CONTEXT.md`.
2. Read `09_HANDOFFS/SESSION_HANDOFF.md`.
3. Use `01_MASTER_PLAN/MASTER_PLAN.md` and `02_ROADMAP/ROADMAP.md` to determine the current phase.
4. Pull work from `03_BACKLOG/ARTIFACT_BACKLOG.md`.
5. Create or refine artifacts using the relevant workflow, prompt, governance, or skill file.
6. End the session by updating `09_HANDOFFS/SESSION_HANDOFF.md` with current status, decisions, files changed, open questions, and the next best prompt.

## Current phase

**Phase 0: Project Setup and Operating Rules**

Phase 0 establishes the safe project scaffold, operating rules, source-of-truth files, and first starter artifacts. It intentionally avoids code, databases, APIs, packages, frontend/backend scaffolds, deployment configs, or employer-specific data.

## Design principle

ATLAS should remain useful even if the only approved workplace AI tool is Gemini Enterprise inside Google Workspace. Every workflow should also be portable to future approved systems such as Microsoft Copilot, internal LLMs, approved APIs, MCP, Claude, OpenAI, or other enterprise tooling.
